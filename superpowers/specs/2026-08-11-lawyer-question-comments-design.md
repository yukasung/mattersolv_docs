# ความเห็นจากทนายบนหน้าคำถาม

## เป้าหมาย

ให้ทนายเปิดหน้า `https://mattersolv-docs.vercel.app/docs/questions/[issueId]`
แล้วส่งความเห็นต่อคำถาม requirement ได้ทันที โดยไม่ต้องเข้าสู่ระบบ และให้ทุกคน
เปิดดูความเห็นย้อนหลังกับวันที่ของความเห็นล่าสุดได้

## ขอบเขต

- แสดงและส่งความเห็นเฉพาะหน้าคำถาม `/docs/questions/[issueId]`
- ผู้ส่งกรอก `ชื่อทนาย` และ `ความเห็น` ซึ่งเป็นข้อมูลบังคับ
- หลังส่งสำเร็จ ความเห็นเผยแพร่ทันทีต่อผู้เยี่ยมชมทุกคน
- หนึ่งคำถามมีได้หลายความเห็น ทั้งจากคนเดิมและหลายคน
- เรียงความเห็นจากใหม่ไปเก่า พร้อมชื่อทนายและวันเวลาในเขตเวลาไทย
- หน้ารวมคำถามแสดงวันที่และเวลาของความเห็นล่าสุดของแต่ละคำถาม
- จำชื่อทนายใน `localStorage` ของเบราว์เซอร์เพื่อเติมในฟอร์มหน้าถัดไป;
  ผู้ใช้แก้ไขหรือล้างชื่อได้

## การคงประวัติ

ความเห็น requirement เป็นบันทึกการตัดสินใจ จึงไม่เปิดให้แก้ไขหรือลบผ่านหน้าเว็บ
ทุกความเห็นที่ส่งสำเร็จเป็นรายการใหม่และคงอยู่ในประวัติ ระบบไม่มีหน้าผู้ดูแล
และไม่มีการซ่อนความเห็นตามขอบเขตที่ตกลงไว้

## สถาปัตยกรรม

ใช้ Turso เป็นฐานข้อมูล SQLite แบบ hosted แทนไฟล์ SQLite ใน Vercel ซึ่งไม่ถาวร
เมื่อ deploy เป็น serverless function

ตาราง `question_comments` มีข้อมูลอย่างน้อยดังนี้:

| ฟิลด์ | ความหมาย |
| --- | --- |
| `id` | รหัส UUID ของความเห็น |
| `issue_id` | เลขคำถาม Linear เช่น `DEV-187` |
| `lawyer_name` | ชื่อทนายที่กรอก |
| `body` | ข้อความความเห็น |
| `created_at` | เวลาส่งแบบ UTC |

หน้า question อ่านรายการจาก API ตาม `issue_id`; client component ส่งความเห็นใหม่
ผ่าน API แล้วเพิ่มรายการที่บันทึกสำเร็จลงบนหน้าทันที หน้ารวมคำถามอ่านค่า
`MAX(created_at)` ต่อ `issue_id` เพื่อแสดงวันที่ล่าสุด

## ความปลอดภัยและความทนทาน

- ยืนยัน Cloudflare Turnstile ที่ API ก่อนบันทึก เพื่อกันบอต
- จำกัดจำนวนการส่งต่อ IP และต่อคำถามในช่วงเวลาหนึ่ง
- ตรวจชื่อและข้อความทั้งฝั่ง client และ server รวมถึงความยาวสูงสุด
- escape/render เป็นข้อความธรรมดา ห้าม render HTML หรือ Markdown จาก comment
- เก็บ URL ของ Turso และ token ไว้เฉพาะ Vercel environment variables
- ตั้งการสำรองข้อมูลรายวันนอกฐานข้อมูลหลัก และทดสอบการกู้คืนเป็นระยะ

เนื่องจากไม่ต้อง login ระบบยืนยันไม่ได้ว่าผู้กรอกชื่อเป็นทนายคนนั้นจริง การป้องกัน
ข้างต้นลดสแปม แต่ไม่ใช่การพิสูจน์ตัวตน

## ข้อผิดพลาดที่ผู้ใช้เห็น

- ฟอร์มระบุช่องที่ต้องกรอก และไม่ส่งเมื่อข้อมูลไม่ครบ
- หาก Turnstile, rate limit หรือฐานข้อมูลไม่พร้อม ให้แสดงข้อความส่งไม่สำเร็จ
  โดยคงข้อความในฟอร์มไว้เพื่อให้ส่งใหม่ได้
- ห้ามแสดง token, SQL หรือรายละเอียดระบบแก่ผู้ใช้

## การทดสอบ

- unit test สำหรับ validation, การบันทึก, การอ่านตาม `issue_id` และวันที่ล่าสุด
- component test สำหรับการจำ/ล้างชื่อใน `localStorage` และการส่งหลาย comment
- test ว่าไม่ render HTML ที่อยู่ในข้อความ comment
- browser test ของ flow: เปิด DEV-187, ส่ง comment, เปิดหน้าคำถามอื่น,
  ตรวจชื่อที่เติมให้อัตโนมัติและประวัติที่แสดง

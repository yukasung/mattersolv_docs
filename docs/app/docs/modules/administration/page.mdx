# Administration

โมดูลผู้ดูแลระบบครอบคลุมงานสองระดับ คือการดูแลแพลตฟอร์มที่มีหลายสำนักงานใช้ร่วมกัน
และการตั้งค่าภายในของแต่ละสำนักงาน รวมถึงข้อมูลกลาง การแจ้งเตือน
และร่องรอยการใช้งานที่ตรวจย้อนหลังได้

ผู้ใช้หลักคือผู้ดูแลระบบของแพลตฟอร์มและผู้ดูแลระบบของสำนักงานแต่ละแห่ง

## Key Capabilities

### Tenant และแพ็กเกจ

- เปิด Workspace ให้สำนักงานใหม่ พร้อม BU Account และ domain หรือ sub-domain
- กำหนดแพ็กเกจการใช้งานที่ควบคุมว่าเปิดใช้โมดูลใดได้บ้าง
- ควบคุมจำนวน user สูงสุดต่อองค์กรตามแพ็กเกจ โดยแผนที่ใช้อยู่ปัจจุบัน
  ตั้งค่าเป็นไม่จำกัดทุกแผน
- ควบคุมสถานะการใช้งานขององค์กร เช่น เปิดใช้ ระงับ หรือยกเลิก

### ผู้ใช้งานและสิทธิ์

- จัดการผู้ใช้งาน role และ permission ภายในองค์กร
- กำหนดสิทธิ์เฉพาะบุคคลเพิ่มเติมจาก role พื้นฐาน
- ดูรายละเอียดที่ [Roles](/docs/roles) และ [Permissions](/docs/roles/permissions)

## System Settings

`System Settings` เป็นค่าพื้นฐานระดับ Workspace ไม่ใช่ค่ากลางของทุกสำนักงาน
ผู้ดูแลสำนักงานใช้หน้านี้เตรียมข้อมูลที่ต้องปรากฏในเอกสารและควบคุมบัญชีที่เข้าใช้
Workspace ของตน การเปลี่ยนค่าในสำนักงานหนึ่งต้องไม่กระทบสำนักงานอื่น

### ข้อมูลองค์กร

- ชื่อสำนักงาน ที่อยู่ เลขประจำตัวผู้เสียภาษี เว็บไซต์ และอีเมลบริษัท
- ข้อมูลนี้เป็นข้อมูลอ้างอิงสำหรับเอกสารของสำนักงาน จึงต้องตรวจสอบชื่อสำนักงาน
  และรูปแบบอีเมลหรือเว็บไซต์ก่อนบันทึก

### เลขรันเอกสาร

- กำหนดคำนำหน้ารหัสสำหรับ Matter, Quotation, Employee และ Client
- คำนำหน้าช่วยให้แยกประเภทข้อมูลได้ง่าย แต่การออกเลขลำดับจริงต้องเป็นหน้าที่ของ
  backend เพื่อป้องกันเลขซ้ำเมื่อมีผู้ใช้หลายคนทำงานพร้อมกัน

### ภาษา

- ผู้ใช้เลือกภาษาไทยหรืออังกฤษสำหรับการแสดงผลของเบราว์เซอร์ที่กำลังใช้งาน
- ภาษาสำหรับการแสดงผลไม่เปลี่ยนข้อมูลของ Workspace หรือเนื้อหาเอกสารที่บันทึกไว้

## Users

`User account` คือบัญชีที่ยืนยันตัวตนและเข้าใช้ MatterSolv ใน Workspace หนึ่ง
บัญชีมีข้อมูลชื่อ อีเมล โทรศัพท์ Role สถานะใช้งาน ภาษา และสิทธิ์เฉพาะบุคคล

ผู้ดูแลสำนักงานสามารถสร้างหรือแก้ไขบัญชี เชิญผู้ใช้ด้วยอีเมล เปลี่ยนรหัสผ่าน
และปิดใช้งานบัญชีได้ การปิดใช้งานต้องระงับการเข้าสู่ระบบโดยไม่ลบประวัติการทำงาน
หรือ Audit Log ของบัญชีนั้น และ Workspace ต้องมีบัญชีผู้ดูแลระบบที่ใช้งานได้อย่างน้อยหนึ่งบัญชี

Role กำหนดสิทธิ์พื้นฐาน ส่วน Permission เฉพาะบุคคลใช้เพิ่มหรือลดขอบเขตจาก Role
โดย backend เป็นผู้บังคับใช้จริง ไม่ให้ชื่อ Role หรือสถานะในหน้าจอเป็นแหล่งตัดสินสิทธิ์เพียงอย่างเดียว

### ความสัมพันธ์กับพนักงาน

`User account` และ `Employee record` เป็นข้อมูลคนละชุด:

- พนักงานอาจยังไม่มีบัญชีเข้าใช้ระบบได้ เช่น บุคลากรที่ไม่ต้องใช้งาน MatterSolv
- ผู้ใช้ที่ได้รับเชิญสามารถเชื่อมกับทะเบียนพนักงานที่มีอยู่ได้หนึ่งรายการ
- การเชื่อมบัญชีช่วยให้ใช้ข้อมูลเดียวกันกับการมอบหมายงาน การเห็นข้อมูล และ Audit Log
  แต่ไม่ควรสร้างหรือปิดทะเบียนพนักงานโดยอัตโนมัติ

ดูรายละเอียดข้อมูลบุคลากรและ lifecycle ของพนักงานที่
[Employees](/docs/modules/employees)

### ข้อมูลกลางของระบบ

- ข้อมูลศาล เขตอำนาจศาล และสถานีตำรวจที่ใช้ร่วมกันทั้งระบบ
- รหัสคดีและประเภท Court Case (คดีศาล) ตามมาตรฐานศาลยุติธรรม
- ข้อมูลกลางเหล่านี้เป็นต้นทางของฟอร์มเอกสารศาลใน
  [Documents](/docs/modules/documents)

### การสื่อสารและการแจ้งเตือน

- ตั้งค่าอีเมลและการแจ้งเตือนของระบบ
- ประกาศจากผู้ดูแลระบบถึงผู้ใช้ทั้งองค์กร
- บันทึกประวัติการติดต่อทุกช่องทาง และค้นย้อนหลังตามแฟ้มงานกฎหมายหรือลูกความ
- ระบบแจ้งปัญหาและคลังความรู้สำหรับผู้ใช้งาน

### ความปลอดภัยและการตรวจสอบ

- บันทึกประวัติการใช้งาน (Audit Log) ว่าใครทำอะไรเมื่อใด
- ตรวจสอบการเข้าถึงระบบ
- แยกข้อมูลของแต่ละองค์กรออกจากกัน
- ติดตามสถานะระบบและจำนวนผู้ใช้งานพร้อมกัน
- สำรองข้อมูลอัตโนมัติ

งาน Security และ Compliance ส่วนขยาย เช่น การปฏิบัติตามมาตรฐาน PDPA/GDPR,
ISO 27001, การตรวจสอบความปลอดภัยภายใน และการทดสอบการกู้คืนข้อมูล
ยังไม่ได้รับการอนุมัติให้เปิดใช้ในรอบนี้

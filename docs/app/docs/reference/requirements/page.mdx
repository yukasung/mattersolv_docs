# Requirement Register

ทะเบียน requirement ต้นทางของระบบ ใช้ตรวจว่าความสามารถหนึ่งถูกระบุไว้อย่างไร
ได้รับการยืนยันแล้วหรือไม่ และมีความพร้อมด้าน Design, Development และ User Test
เพียงใด โดยแยก **สถานะการยืนยัน requirement** ออกจาก **สถานะความพร้อมส่งมอบ**
เสมอ

คอลัมน์ **แถว** คือหมายเลขแถวในไฟล์ต้นทาง ใช้อ้างอิงย้อนกลับได้
ส่วนคอลัมน์เลขข้อในไฟล์ต้นทางไม่ถูกนำมาแสดงเพราะ Excel เก็บ `1.10` เป็น `1.1`
ทำให้ซ้ำกับข้อ `1.1` จริง

ตรวจเทียบ source ล่าสุดเมื่อ **14 August 2026**

## Status Model

| แกนสถานะ | ค่า | ความหมาย |
| --- | --- | --- |
| Requirement decision | `Passed` | Requirement ได้รับการตกลงใน baseline แล้ว ไม่ได้หมายความว่าพัฒนา ทดสอบ หรือเปิดใช้งานเสร็จ |
| Requirement decision | `Waiting to Confirm` | Requirement ยังขาดคำยืนยันหรือรายละเอียด ห้ามนำไปกำหนด production behavior โดยการคาดเดา |
| Delivery readiness | `Pass` | Design, Development และ User Test ผ่านตามหลักฐานของ Action Plan |
| Delivery readiness | `Partially Pass` | มีงานหรือหลักฐานบางส่วน แต่ยังไม่ครบทุกขั้นที่ Action Plan ประเมิน |
| Delivery readiness | `Not Pass` | ยังไม่ผ่านการประเมินความพร้อมส่งมอบ ไม่ได้หมายความว่า requirement ถูกปฏิเสธ |
| Delivery readiness | `Not Applicable` | ขั้นหรือการประเมินนั้นยังไม่ใช้กับรายการดังกล่าว ต้องไม่ตีความเป็นผ่านหรือยกเลิก requirement |

> `Passed` ใน Requirement baseline ไม่เท่ากับ `Pass` ใน Action Plan และห้ามใช้
> สถานะจากแกนหนึ่งเขียนทับอีกแกนหนึ่ง

## Reconciliation Rules

- รักษา 181 baseline requirements ด้านล่างไว้จนกว่าจะมี approved decision เปลี่ยน
  scope หรือยกเลิกรายการ
- Action Plan มีระดับรายละเอียดและตำแหน่งแถวต่างจาก baseline จึงยังไม่ถือว่า
  จับคู่กันแบบหนึ่งต่อหนึ่ง
- ก่อนรวมสถานะรายข้อ ต้องบันทึกอย่างน้อย `Canonical Requirement ID`, baseline
  row, Action Plan row, domain, requirement decision, delivery readiness,
  mapping status และ decision/evidence reference
- ใช้สถานะ `Unmapped`, `Candidate` และ `Confirmed` สำหรับการจับคู่ โดยมีเฉพาะ
  `Confirmed` ที่นำไปสรุป coverage ราย requirement ได้
- ห้ามสรุปว่าฟีเจอร์พร้อม release จาก `Passed` เพียงค่าเดียว และห้ามสรุปว่า
  requirement ถูกตัดออกจาก `Not Pass` หรือ `Not Applicable` เพียงค่าเดียว
